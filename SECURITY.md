# Security Policy

## Supported Versions

Liner Notes is under active development. Security fixes target the latest commit
on the `Prism` development branch. There is currently no maintained stable release
line, and fixes are not backported to historical versions.

| Version | Supported with security fixes |
| ------- | ----------------------------- |
| Latest commit on `Prism` | Yes |
| Historical versions and other branches | No |

Development support does not mean the project is ready for production use.

## Reporting a Vulnerability

Report suspected vulnerabilities privately through
[GitHub's vulnerability reporting form](https://github.com/Jafarli-Mahammad/Liner-Notes/security/advisories/new).
You can also find it under the repository's security advisories by selecting
**Report a vulnerability**.

If private reporting is unavailable, open an issue asking the maintainer for a
private contact method. Include no vulnerability details in that issue. Do not
disclose vulnerabilities in public issues, pull requests, or discussions before
coordinating with the maintainer.

Please include:

- The affected commit or version and relevant configuration.
- A description of the vulnerability and its potential impact.
- Steps to reproduce it, preferably with a minimal proof of concept.
- Relevant logs or screenshots with secrets and personal data removed.
- Any suggested mitigation, if available.

Use a local environment and accounts you control when reproducing a problem.
Do not access other users' data or test third-party services without their
permission. Never include real passwords, API keys, session tokens, or user data
in a report.

### What to Expect

We aim to acknowledge reports within **14 calendar days** and provide an update
at least every **30 calendar days** while a report remains open. These are response
targets for a small volunteer project, not guaranteed deadlines. If you have not
received a response, follow up in the private report.

If a report is accepted, we will discuss its impact, any available mitigation,
and a plan for a fix. Fix timing depends on severity and the work required. We
will coordinate public disclosure after a fix or mitigation is available and
credit the reporter with their permission.

If a report is declined, we will explain why, such as an inability to reproduce
the issue, a duplicate report, or a finding outside this project's scope. You
can provide further evidence for reconsideration.

For ordinary bugs and feature requests, use
[GitHub issues](https://github.com/Jafarli-Mahammad/Liner-Notes/issues).
